01 — nomenclatura

Sugestão de nome

Quatro candidatos avaliados por adequação ao conceito: execução efêmera, sem rastro de instalação, disponível em qualquer máquina.

✦ recomendado
AUTOTASK LIVE
Direto, familiar, complementa o nome atual. "Live" evoca execução ao vivo — sem persistência de código, apenas ação. Mantém a família AUTOTASK legível.
AUTOTASK NOMAD
Evoca portabilidade total — roda em qualquer máquina sem pertencer a nenhuma. Conceito forte, mas diverge visualmente do padrão.
AUTOTASK GHOST
Não instala nada, não deixa rastro de código — apenas logs. Criativo, mas pode ser ambíguo para documentação técnica futura.
AUTOTASK RUN
Imperativo, minimalista. Descrição exata da função. Menos personalidade, mais precisão técnica. Bom para uso corporativo futuro.
Convenção adotada neste documento: AUTOTASK LIVE — referenciado no código como autotask-live e no Gist como launcher.ps1.

Estrutura criada no Desktop

Ao rodar pela primeira vez, o launcher cria a seguinte estrutura. Nas execuções seguintes, apenas sobrescreve os scripts com a versão atual do repo.

Desktop\AUTOTASK\
├── scripts\ ← cópias dos .py baixados do repo
│ ├── file_organize_downloads.py
│ ├── sync_compress_vault.py
│ └── sys_clean_temp.py
└── logs\ ← gerada pelos scripts via __file__ resolution
├── organize_dougf_2026-05-26.log
└── vault_dougf_2026-05-26.log
Por que funciona com os scripts sem modificação: os scripts resolvem o diretório de logs via Path(__file__).resolve().parent.parent / "logs". Como __file__ aponta para Desktop\AUTOTASK\scripts\script.py, parent.parent resolve para Desktop\AUTOTASK\ — onde o launcher já criou a pasta logs\. Zero alteração nos scripts.
04 — componentes

Especificação dos componentes

A. GitHub Personal Access Token (PAT)

O PAT autentica a chamada à GitHub API para baixar os scripts do repo privado. Deve ser configurado com permissões mínimas.

  • PERM Scope requerido: repo → Contents: Read-only. Nenhuma outra permissão é necessária.
  • EXP Expiração recomendada: 90 dias com renovação manual. Tokens que não expiram são risco desnecessário.
  • LOCAL Onde fica: embutido no launcher.ps1 dentro do Gist secreto. Nunca exposto publicamente.

Para criar: GitHub → Settings → Developer Settings → Personal Access Tokens → Fine-grained → selecionar o repo autotask → Contents: Read.

B. Gist Secreto

O Gist secreto hospeda o launcher.ps1. Não é indexado por buscadores, não aparece no perfil público do GitHub — mas qualquer pessoa com a URL pode acessar.

  • URL Formato da URL raw: https://gist.githubusercontent.com/USUARIO/GIST_ID/raw/launcher.ps1 — esta é a URL do one-liner.
  • SEC Não compartilhar a URL: ela contém o acesso ao launcher que por sua vez contém o PAT. Tratar como credencial.
  • UPD Atualização: editar o Gist regenera um novo hash na URL raw. Atualizar o one-liner salvo sempre que editar o Gist.

C. launcher.ps1 — código completo

O script que roda em memória via irm | iex. Baixa os scripts do repo, monta a estrutura no Desktop e exibe o menu.

# launcher.ps1 — AUTOTASK LIVE
# Hospedado em Gist Secreto. Não commitar no repo.

$token   = "ghp_SEU_TOKEN_AQUI"
$repo    = "furbas16e8/autotask"
$branch  = "main"
$headers = @{ Authorization = "token $token"; "User-Agent" = "PowerShell" }

# Estrutura no Desktop
$desktop = [Environment]::GetFolderPath('Desktop')
$runDir  = Join-Path $desktop "AUTOTASK"
$scripts = Join-Path $runDir "scripts"
$logs    = Join-Path $runDir "logs"

New-Item -ItemType Directory -Force -Path $scripts | Out-Null
New-Item -ItemType Directory -Force -Path $logs    | Out-Null

# Catálogo de scripts disponíveis
$menu = [ordered]@{
    "1" = @{ file = "file_organize_downloads.py"; label = "Organizar Downloads" }
    "2" = @{ file = "sync_compress_vault.py";    label = "Backup do Vault (Obsidian)" }
    "3" = @{ file = "sys_clean_temp.py";         label = "Limpar Temp do Sistema" }
}

# Interface
Clear-Host
Write-Host ""
Write-Host "  AUTOTASK LIVE"                -ForegroundColor White
Write-Host "  ──────────────────────────────" -ForegroundColor DarkGray
$menu.GetEnumerator() | ForEach-Object {
    Write-Host "  [$($_.Key)]  $($_.Value.label)" -ForegroundColor Gray
}
Write-Host "  ──────────────────────────────" -ForegroundColor DarkGray
$choice = Read-Host "  Escolha"

if (-not $menu.Contains($choice)) {
    Write-Host "  Opção inválida." -ForegroundColor Red
    exit 1
}

# Baixa o script escolhido via GitHub API
$selected = $menu[$choice]
$apiUrl   = "https://api.github.com/repos/$repo/contents/scripts/$($selected.file)?ref=$branch"
$outFile  = Join-Path $scripts $selected.file

try {
    Write-Host "  Baixando $($selected.file)..." -ForegroundColor DarkGray
    $content = Invoke-RestMethod -Uri $apiUrl -Headers $headers
    $bytes   = [Convert]::FromBase64String($content.content)
    [System.IO.File]::WriteAllBytes($outFile, $bytes)
} catch {
    Write-Host "  Erro ao baixar script: $_" -ForegroundColor Red
    exit 1
}

# Detecta Python real (regra AGENTS.md §3)
$pythonCmd = (Get-Command -All python |
    Where-Object { $_.Path -notlike "*WindowsApps*" } |
    Select-Object -First 1).Path
if (-not $pythonCmd) { $pythonCmd = "python" }

# Executa
Write-Host "  Executando $($selected.label)..." -ForegroundColor White
Write-Host ""
& $pythonCmd $outFile
05 — implementação

Passos de implementação

  1. Criar o Personal Access Token

    No GitHub: Settings → Developer Settings → Personal Access Tokens → Fine-grained tokens → Generate new token.

    Configurar: nome autotask-live, expiração 90 dias, escopo restrito ao repo autotask, permissão Contents: Read-only. Copiar o token gerado.

  2. Montar o launcher.ps1

    Usar o código da seção anterior. Substituir ghp_SEU_TOKEN_AQUI pelo PAT gerado no passo 1. Confirmar o nome correto do repo em $repo.

  3. Criar o Gist Secreto

    Acessar gist.github.com. Criar novo Gist com visibilidade Secret. Nomear o arquivo launcher.ps1. Colar o conteúdo do passo 2. Salvar.

    Acessar o arquivo dentro do Gist, clicar em Raw e copiar a URL completa — essa é a URL do one-liner.

  4. Testar o one-liner

    Abrir o PowerShell (sem necessidade de admin para a maioria dos scripts) e rodar:

    irm https://gist.githubusercontent.com/furbas16e8/GIST_ID/raw/launcher.ps1 | iex

    Verificar se a pasta Desktop\AUTOTASK\ é criada, o menu aparece e o script executa corretamente.

  5. Salvar o one-liner em local acessível

    Opções: salvar como nota no TickTick, bloco de notas no Obsidian (fora do vault público), ou como alias no perfil do PowerShell da máquina principal:

    # No $PROFILE da máquina principal (opcional)
function autotask-live {
    irm "https://gist.githubusercontent.com/furbas16e8/GIST_ID/raw/launcher.ps1" | iex
}

  6. Renovar o PAT antes do vencimento

    Criar calendário de renovação a cada 90 dias. Ao renovar: gerar novo PAT, editar o Gist com o novo token. A URL do Gist muda ao editar — atualizar o one-liner salvo.

06 — segurança

Considerações de segurança

Exposição do PAT

O PAT fica no Gist secreto, não em repositório público. O risco é a URL do Gist vazar. Tratar a URL como credencial — não compartilhar, não colar em chats.

Permissão mínima

O PAT tem acesso de leitura apenas ao conteúdo do repo autotask. Um vazamento não permite escrita, criação de issues ou acesso a outros repos.

Execução em memória

O launcher.ps1 nunca é salvo em disco — executa direto da pipe do PowerShell. Os scripts Python sim são salvos no Desktop, mas sem dados sensíveis.

Scripts sobrescritos

A cada execução, o script baixado sobrescreve o anterior. Não é possível adulteração local persistente — a fonte é sempre o repo no GitHub.

Rotação recomendada: ao suspeitar que a URL do Gist foi exposta — deletar o Gist, revogar o PAT, criar ambos novamente e atualizar o one-liner salvo.
07 — restrições e dependências

O que é necessário

  • REQ Python 3.10+ instalado fora do WindowsApps — detectado automaticamente pelo launcher conforme AGENTS.md §3.
  • REQ Conexão com internet — a GitHub API precisa ser acessível. Em redes corporativas com proxy, configurar $env:HTTPS_PROXY antes do one-liner.
  • REQ py7zr instalada — necessária para sync_compress_vault.py. Se ausente, o script exibe alerta instrucional (comportamento já implementado no script).
  • OBS sys_clean_temp.py requer PowerShell com permissão de administrador para limpar C:\Windows\Temp. Os outros scripts rodam sem admin.
  • NOTE Política de execução do PowerShell precisa permitir scripts remotos. Verificar com Get-ExecutionPolicy — se Restricted, rodar Set-ExecutionPolicy RemoteSigned -Scope CurrentUser uma vez.
08 — extensibilidade

Adicionando novos scripts

Para incluir um novo script no menu do AUTOTASK LIVE, apenas duas edições são necessárias — nenhuma mudança na estrutura do launcher.

1. Adicionar o arquivo .py na pasta scripts/ do repo e commitar.

2. Editar o Gist: adicionar uma entrada no dicionário $menu do launcher: 

$menu = [ordered]@{
    "1" = @{ file = "file_organize_downloads.py"; label = "Organizar Downloads" }
    "2" = @{ file = "sync_compress_vault.py";    label = "Backup do Vault" }
    "3" = @{ file = "sys_clean_temp.py";         label = "Limpar Temp" }
    "4" = @{ file = "novo_script.py";            label = "Nova Automação" }  ← adicionar
}
Lembrar que editar o Gist altera o hash da URL raw. Atualizar o one-liner salvo após qualquer edição no Gist.
